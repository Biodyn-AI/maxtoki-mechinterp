# Stage 4 — Interactive Web Atlas Deployment for SAE Feature Atlases

## 1. Overview

This pipeline documents how to create and deploy a **comprehensive interactive web atlas** for a single-cell foundation model's SAE feature decomposition. The atlas is the public-facing deliverable of Stages 1–3: it presents the complete feature catalog, ontology annotations, co-activation modules, cross-layer information flow, causal patching results, perturbation response mapping, gene search, and pathway search in an interactive web application served via GitHub Pages.

The architecture is a **React 19 + TypeScript + Vite + Tailwind CSS** single-page application with **Plotly.js** for interactive data visualization. All data is served as static JSON files from the same repository — no backend server required. The reference implementations are:

- **Geneformer atlas:** [`Biodyn-AI/geneformer-atlas`](https://github.com/Biodyn-AI/geneformer-atlas) → [biodyn-ai.github.io/geneformer-atlas/](https://biodyn-ai.github.io/geneformer-atlas/) — 82,525 features × 18 layers, ~166 MB data, 9 interactive pages.
- **scGPT atlas:** [`Biodyn-AI/scgpt-atlas`](https://github.com/Biodyn-AI/scgpt-atlas) → [biodyn-ai.github.io/scgpt-atlas/](https://biodyn-ai.github.io/scgpt-atlas/) — 24,527 features × 12 layers.
- **MaxToki atlas:** [`Biodyn-AI/maxtoki-atlas`](https://github.com/Biodyn-AI/maxtoki-atlas) → [biodyn-ai.github.io/maxtoki-atlas/](https://biodyn-ai.github.io/maxtoki-atlas/) — 56,702 alive features (39,128 annotated, 333,623 enrichments) × 12 layers (4,928 features/layer dictionary).

## 2. Source

- **Reference implementation:** [`Biodyn-AI/geneformer-atlas`](https://github.com/Biodyn-AI/geneformer-atlas) — the canonical template. All new atlases should fork or adapt this codebase.
- **SAE methodology paper:** the prior work, arXiv:2603.02952.
- **Web atlas source:** The atlas is NOT generated by the SAE training pipeline (Stages 1–3). It is a separate engineering deliverable that consumes the JSON artefacts produced by Stages 1–3.

## 4. JSON Data File Schema

The atlas is powered by ~20 static JSON files in `public/data/`. Each file has a strict schema documented below.

### 4.1 `global_summary.json`

```json
{
  "model": "MaxToki-217M",
  "total_features": 59136,
  "total_alive": 56702,
  "total_annotated": 39128,
  "total_enrichments": 333623,
  "n_layers": 12,
  "features_per_layer": 4928,
  "d_model": 1232,
  "d_sae": 4928,
  "k": 32,
  "layers": [
    {
      "layer": 0,
      "alive": 2498,
      "dead": 2430,
      "annotated": 2016,
      "annotation_rate": 0.807,
      "n_modules": 10,
      "n_svd_aligned": 0,
      "n_novel": 2498,
      "ontology_counts": {"GO_BP": 9005, "KEGG": 1993, "Reactome": 11453, "TRRUST": 623},
      "variance_explained": 0.693,
      "mean_feature_cosine": 0.025
    },
    ...
  ]
}
```

### 4.2 `layer_XX_features.json`

Array of `FeatureCompact` objects (one per dictionary element):

```json
[
  {
    "i": 0,           // feature index
    "d": 0,           // 0=alive, 1=dead
    "f": 0.00654,     // activation frequency
    "ma": 2.341,      // max activation
    "fc": 6540,       // fire count (freq × 1M)
    "na": 12,         // number of significant annotations
    "m": 3,           // module assignment (-1 if none)
    "sv": 0,          // SVD-aligned flag (1 if cosine > 0.7 with top-50 SV)
    "lb": "Cell cycle G2/M",  // best annotation label
    "to": "GO_BP",    // top ontology source
    "tg": [           // top 5 genes
      {"n": "CDK1", "a": 0.892},
      {"n": "CDC20", "a": 0.756},
      ...
    ]
  },
  ...
]
```

### 4.3 `layer_XX_positions.json`

Array of `[x, y]` UMAP coordinates, parallel to the features array:

```json
[[1.234, -0.567], [2.345, 0.891], ...]
```

### 4.4 `layer_XX_annotations.json`

Dict keyed by feature index (as string):

```json
{
  "42": {
    "genes": [
      {"n": "CDK1", "a": 0.892, "fc": 100},
      {"n": "CDC20", "a": 0.756, "fc": 95},
      ...
    ],
    "anns": [
      {
        "o": "GO_BP",           // ontology source
        "t": "Cell cycle G2/M", // term name
        "p": 0.00001,           // BH-corrected p-value
        "or": 15.4,             // odds ratio
        "n": 8,                 // overlap size
        "g": ["CDK1", "CDC20"]  // overlap genes
      },
      ...
    ]
  }
}
```

### 4.5 `modules.json`

```json
[
  {
    "layer": 0,
    "id": 0,
    "n": 456,            // number of features
    "features": [0, 3, 7, ...],  // feature indices (capped at 100 for file size)
    "top_anns": [
      {"t": "Cell Cycle", "c": 234},  // term + count
      ...
    ]
  },
  ...
]
```

### 4.6 `gene_index.json`

```json
{
  "CDK1": [
    {"l": 0, "i": 42, "r": 0, "lb": "Cell cycle G2/M", "m": 3},
    {"l": 5, "i": 1205, "r": 2, "lb": "Mitosis", "m": 1},
    ...
  ],
  ...
}
```

### 4.7 `ontology_index.json`

```json
{
  "Cell cycle G2/M": [
    {"l": 0, "i": 42, "p": 0.00001, "o": "GO_BP"},
    {"l": 5, "i": 1205, "p": 0.0003, "o": "KEGG"},
    ...
  ],
  ...
}
```

### 4.8 Other files

- **`cross_layer_tracking.json`** — persistence rates between adjacent layers
- **`cross_layer_graph.json`** — per-pair summary + top dependencies (PMI)
- **`svd_comparison.json`** — per-layer SVD vs SAE variance explained + aligned/novel counts
- **`causal_patching.json`** — 50 features with specificity ratios + target/off-target logit changes
- **`perturbation_response.json`** — 100 CRISPRi targets with responding feature lists
- **`layer_XX_celltypes.json`** (optional) — per-feature cell-type and tissue enrichments

## 5. Atlas Architecture

### 5.1 Pages

| Route | Component | Description |
|---|---|---|
| `/` | `Overview.tsx` | Dashboard: hero, stat cards, annotation/ontology charts, key findings links |
| `/layer/:layerId` | `LayerExplorer.tsx` | 3-panel layout: layer selector + UMAP scatter + feature detail sidebar |
| `/feature/:layerId/:featureId` | `FeaturePage.tsx` | Full feature detail: genes, annotations, cell types, causal patching, perturbation response |
| `/modules` | `ModuleExplorer.tsx` | Module cards with filter/sort, expandable feature lists |
| `/flow` | `CrossLayerFlow.tsx` | Persistence chart + layer-pair selector + top dependencies table |
| `/genes` | `GeneSearch.tsx` | Autocomplete search → layer×rank scatter + results table |
| `/pathways` | `OntologySearch.tsx` | Autocomplete search → stacked bar chart + results table |
| `/comparisons` | `Comparisons.tsx` | SVD vs SAE bars, persistence chart, causal specificity bars |
| `/about` | `About.tsx` | Model info, methodology, links |

### 5.2 Key design patterns

- **Dark theme** (slate-950 bg, slate-900/60 cards, backdrop-blur glassmorphism)
- **DM Sans / Inter + JetBrains Mono** typography
- **Brand color**: sky blue (#0ea5e9) with purple accents
- **InfoIcon tooltips** on every significant label
- **Plotly charts** with transparent backgrounds, dark gridlines
- **Lazy data loading** via `useData` hook with in-memory cache
- **Hash routing** (`HashRouter`) for GitHub Pages compatibility
- **Responsive** down to mobile (768px breakpoint)

## 6. Deployment Steps

### Step 1 — Generate JSON data files

Run the SAE pipeline (Stages 1-3) to completion, then generate atlas JSON files from the pipeline outputs. Reference script: `projects/maxtoki/runs/sae-atlas-217M/scripts/phases12_13_viz.py` or the standalone data generation script.

Key conversions:
- Feature catalogs → `layer_XX_features.json` (compact schema)
- Enrichment CSVs → `layer_XX_annotations.json` (per-feature detail)
- UMAP coords → `layer_XX_positions.json` (2D arrays)
- Module labels → `modules.json` (with top annotations)
- Gene→feature mappings → `gene_index.json`
- Ontology term→feature mappings → `ontology_index.json`

### Step 2 — Fork the template atlas

```bash
git clone https://github.com/Biodyn-AI/geneformer-atlas.git my-model-atlas
cd my-model-atlas
```

### Step 3 — Replace data + adapt source

```bash
# Replace data files
rm -rf public/data/*
cp /path/to/generated/data/*.json public/data/

# Update vite.config.ts base path
sed -i "s|/geneformer-atlas/|/my-model-atlas/|g" vite.config.ts

# Update model name throughout source
find src/ -name '*.tsx' -exec sed -i 's/Geneformer/MyModel/g' {} \;

# Update layer configuration (if non-standard)
# Edit src/pages/LayerExplorer.tsx: LAYERS array
# Edit any hardcoded layer counts
```

### Step 4 — Build

```bash
npm install
npx vite build
```

### Step 5 — Deploy to GitHub Pages

```bash
# Option A: Deploy dist/ directly to main branch
git checkout main
cp -R dist/* .
git add -A
git commit -m "Deploy atlas"
git push

# Option B: GitHub Actions (see .github/workflows/deploy.yml in geneformer-atlas)
```

### Step 6 — Enable GitHub Pages

```bash
gh api repos/OWNER/REPO/pages -X POST --input - <<'JSON'
{"source":{"branch":"main","path":"/"}}
JSON
```

## 7. Validation

After deployment, verify:

1. **Overview page loads** with correct stat card values
2. **Layer Explorer** shows UMAP scatter with points, click-to-select works
3. **Feature detail pages** show gene bars, annotation accordion, causal patching (if available)
4. **Gene Search** autocomplete finds known genes (e.g. TP53, CDK1)
5. **Ontology Search** finds pathway terms
6. **Module Explorer** shows module cards with expandable feature lists
7. **Cross-Layer Flow** shows persistence chart
8. **Comparisons** shows SVD vs SAE grouped bars
9. **Mobile layout** is usable (nav collapses, charts resize)

## 8. Known pitfalls

1. **GitHub Pages 100 MB file limit.** Large `gene_index.json` (can be 25+ MB for 18-layer atlases) or `layer_XX_annotations.json` (5+ MB each) may hit limits. Compress by truncating annotation details or splitting into per-layer chunks.
2. **Hash routing required.** GitHub Pages doesn't support SPA routing natively. Use `HashRouter` in react-router-dom, not `BrowserRouter`.
3. **Non-contiguous layers.** If your model has non-contiguous layer IDs (e.g., L0, L5, L11 for a 3-layer subset), the layer selector in `LayerExplorer.tsx` needs to be updated from `Array.from({ length: 18 })` to an explicit array.
4. **Missing data files.** Pages gracefully handle 404 on optional data files (cell types, causal patching) but crash on required files (global_summary, features, positions). Always generate the core 7 file types.
5. **Plotly bundle size.** The Plotly.js chunk is ~4.7 MB (1.4 MB gzipped). Consider `plotly.js-basic-dist-min` if bundle size is critical.
6. **UMAP reproducibility.** UMAP coordinates depend on the random seed AND the data order. Pin both for reproducible layouts across rebuilds.

LLM Usage Statement
====================

This paper is itself about using large language models (LLMs) as
autonomous research agents, so LLM use is unusually pervasive and we
document it in detail below. The submitted work would not exist without
LLM-driven execution; the substantive contribution is the architecture
that makes such execution methodologically defensible (the pipeline-as-
spec contract and the recurring-issue audit framework), together with
the deployment study on MaxToki-217M.

1. AI MODEL USED
----------------

Claude Opus 4.7 (Anthropic), accessed via the Claude Code CLI and the
Anthropic API, was the primary agent throughout. All "agent" references
in the paper refer to this model. We did not use OpenAI, Google, or
other-provider models for the load-bearing experimental work. A small
number of supplementary verification calls (paper-revision sub-reviews
described under section 3 below) used the same Claude model in
parallel.

2. PIPELINE EXECUTION (THE LOAD-BEARING USE)
--------------------------------------------

All eight mech-interp pipelines reported in Section 5 of the paper were
executed end-to-end by Claude agents under high-level human direction.
Concretely, the agent:

  - read the markdown pipeline specification under `pipelines/`;
  - downloaded and loaded the target-model checkpoint (MaxToki-217M,
    scGPT, or Geneformer V2-316M from public HuggingFace releases);
  - extracted hidden states / attention weights via standard
    `transformers` hooks;
  - implemented and trained the analysis components named in the
    spec (e.g., per-layer TopK SAEs, Curveball degree-preserving null
    permutations, bootstrap resamplers, GroupKFold splits);
  - ran null-model hierarchies and cross-condition validation;
  - produced per-pipeline final summaries under
    `projects/maxtoki/summaries/`.

The supervisor (anonymous) interacted at three levels: directional
("run pipeline X on target Y"), methodological ("before launching,
what's the chance baseline you plan to anchor against?"), and gating
(explicit go/no-go on multi-hour SAE training and full residual-stream
re-extractions). The supervisor did not write extraction code, debug
agent runs, or compose summary documents. Total human time: approximately
15 hours of supervision over three weeks of wall clock; total agent
compute: approximately 50 GPU-hours of MaxToki forward passes plus
auxiliary CPU work (SAE training, statistical resampling).

For pipelines with open-ended hypothesis search (the topology-141
pipeline, the manifold-discovery sweep over 12 candidate biological
rulers), the agent operated in an autonomous loop alternating
"brainstormer" and "executor" turns with persistent file-based memory
across conversations, governed by a 2-consecutive-negatives retirement
rule documented in Section 3.3 of the paper.

3. PAPER DRAFTING AND REVISION
------------------------------

The paper text itself was drafted by Claude under human supervision.
Specifically:

  - The initial draft was produced by Claude from per-pipeline final
    summaries plus the audit reports.
  - Five parallel review agents (also Claude) then reviewed the draft
    along five distinct angles: internal consistency / numerical
    correctness, clarity and findings emphasis, draft-artefact removal,
    bibliography validation and expansion, and adversarial
    peer-reviewer-style critique. Each review was written without
    knowledge of the others (independent agent contexts).
  - Reviews were synthesized into an edit plan and applied to the
    draft. The bibliography was expanded from 21 to 48 entries with
    each new entry validated against arXiv / DOI / publisher records
    via web fetches; two existing entries had author-key mismatches
    corrected (one was credited to the wrong first author).
  - The MaxToki-rationale paragraph (Section 4.1), the figures, and
    the spectral-geometry findings subsection (5.6) were added in
    subsequent revision passes.

We treat this multi-pass agent-review-and-revise workflow as a
methodological extension of the audit framework documented in the
paper itself: the audit pipeline polices methodological hygiene of the
experimental work; the multi-reviewer pass polices the manuscript that
reports it.

4. CODE AND ANALYSIS SCRIPT GENERATION
--------------------------------------

The pipeline specifications under `pipelines/` are human-authored
markdown contracts; the executable code that implements them was
generated by Claude during pipeline execution and lives under
`projects/maxtoki/runs/<pipeline>/` (omitted from the anonymous release
because of size; included on de-anonymization). This includes
hidden-state extraction harnesses, SAE training loops, null-model
permutation code, bootstrap CI computation, and figure-generation
scripts.

Three small analysis utilities were generated by Claude during the
audit remediation cycle and are included in the anonymous repository:

  - `projects/maxtoki/audits/audit_a3_bootstrap_cis.py` — non-parametric
    bootstrap CIs over the unit of inference for the headline numbers
    flagged under audit pattern P8;
  - the audit-pattern-application code embedded inside the audit
    reports themselves;
  - the LaTeX figures in the submitted paper (TikZ / pgfplots).

5. VERIFICATION MECHANISMS
--------------------------

Output from LLM-driven execution was verified through five overlapping
mechanisms:

  (a) The recurring-issue audit framework (Section 3.4) was the primary
      verification mechanism. It ran autonomously after each pipeline
      batch, applying ten reviewer-derived methodological diagnostics
      to artefacts produced by prior agent runs and emitting a
      per-pattern verdict matrix and an action-proposal table. This
      caught three load-bearing flaws documented in Section 6 of the
      paper (a sign-tracking error in directional accuracy, an
      unanchored chance baseline for TF specificity, and missing
      bootstrap CIs on six of eight pipelines).

  (b) Cross-pipeline triangulation. Five methodologically distinct
      probes were aggregated under the convergent-negative finding in
      Section 5.1; we explicitly examine their shared assumptions in
      Section 7 ("Common-mode risks for the convergent negative") and
      acknowledge that convergence is evidence within those shared
      assumptions, not evidence about them.

  (c) Cross-cohort validation. The manifold result in Section 5.2 was
      validated on 13 strictly disjoint donors and zero-shot
      transferred to 12 multi-tissue donors, with an explicit
      non-hematopoietic lung negative control that fails 3 of 4 gates
      decisively.

  (d) Permutation null models. Every reported metric is anchored
      against a chance baseline (Curveball degree-preserving null,
      within-branch shuffle null, random-feature draws), with
      bootstrap confidence intervals on the unit of inference.

  (e) Manual spot-checking by the supervisor. Final summary documents
      were read by a human, with random spot-checks of cited numbers
      against underlying CSVs / JSONs in the run directories. The
      supervisor explicitly questioned and traced inconsistencies
      (e.g., "the findings file says A, why does the underlying CSV
      say B?"); two of the three audit-detected failures were first
      noticed during such spot-checks before being formally written
      into a P1/P3/P6/P8 verdict by the audit pipeline.

6. RESIDUAL UNCERTAINTY
-----------------------

We did not formally validate that headlines the audit did NOT flag are
equally reliable. Section 7 of the paper explicitly acknowledges this:
"the residual uncertainty applies symmetrically to un-audited
headlines from non-agent workflows, but the cost profile is
favourable." The audit framework should not be read as a guarantee
of correctness; it is a systematic mitigation that is itself amenable
to extension and external validation, both of which are open work.

7. SCOPE OF AGENT AUTONOMY
--------------------------

The agents executed the human-authored pipeline catalogue and proposed
new hypotheses within existing pipeline structures (the autonomous
loop in Section 3.3), but did not generate novel pipeline architectures.
Pipeline design, the audit checklist, and the project-direction-level
choices (target model, deployment scope, manuscript framing) were
human decisions. We see this as a meaningful constraint on autonomy at
the current generation of agents, not a claim about what is in
principle possible.
